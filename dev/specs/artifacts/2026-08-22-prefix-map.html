Three sources, three answers

hs — hazard setup

Its 10 files sit in graphs/templates/. The study README says distributions/. hvti_taxonomy() now says analyses/, placed straight after the hm it reads via inhaz=est.hmdead.

The case for analyses: hs fits nothing and draws nothing — it turns a model into per-patient predictions. Its output is a dataset, not a figure. It landed in graphs/ because hp is what consumes it.

Disagrees

rfs — random forest survival

The taxonomy files it under analyses/. The one file carrying the name is documents/templates/tp.rfs.analysis.Rnw — a report, not an analysis. Either the taxonomy row is right and that file is misnamed, or rfs means two different things.

Scattered · 4 prefixes

dp spans three folders

31 files: 22 in graphs/, 6 in descriptive/, 3 in distributions/. ce, cd and ar each straddle two. A prefix that names a folder cannot sit in three of them — a scaffolded job has to go somewhere, and the taxonomy picks one.

Documented, never scaffolded

estimates has no prefix

It is the one row that names an artifact kind rather than a job type, so its prefix is NA — nothing scaffolds into it. Its position is still load-bearing: it occupies major 05, which is what pushes graphs to 06 and documents to 07.

30 names that lead a file but name no analysis

How this was built. Actual placement comes from walking ~/Documents/template/*/templates/ and matching tp.<field>. at the head of each filename, all extensions, skipping archive/. The README column is parsed from the prefix table in ~/Documents/template/README.md; blanks mean that prefix is not listed there, not that it disagrees. The taxonomy column is parsed from R/taxonomy.R. One caveat: a prefix appearing in several folders is normal history, not necessarily an error — the corpus accumulated over decades and files were filed by whoever wrote them. The reason to resolve it now is that new_job() has to pick exactly one folder per prefix, and picking it silently is how the README drifted in the first place.
