rfr-fit: Random forest regression: fit

Run sheet

What it does

Grows a regression forest and checks it: out-of-bag error and predicted against observed. See the report it produces on the gallery's synthetic study.

Prerequisites

  • A study. The job runs inside a study folder set up with _study.yml. Start a new study shows how.
  • The study's data. DATASET names the registered dataset it reads ("built" unless you change it). A draft can read a build that is not registered yet, so you can start before the build is final, and the report then says it is a draft. A final render reads registered data only: register the build with hvtiRutilities::update_manifest() first.
  • Packages: randomForestSRC (>= 3.7.0), ggRandomForests (>= 4.0.0), hvtiRutilities. The job checks each floor when it starts, so an older library stops it at the top rather than partway through.

Outline

These are the job's own sections, in order. The detail lives in the template: the comments at each EDIT: marker say what to set and why, and Work a job shows three ways to find them.

  1. Above the first section: 1 choice marked EDIT:.
  2. Study choices: 9 choices marked EDIT:.
  3. Cohort: reads the study data.
  4. Forest: fits and caches its results, so a later render reloads them (REFIT <- TRUE recomputes them).
  5. Does the forest work?: saves rfr.rds, which rfr-explain reads.

Run it

Render a draft as you go. render_job(job) runs the whole job in a clean R session and writes the report beside it. Render early and often: while any EDIT: marker is left, the report opens with a DRAFT banner listing them, and its numbers are not a result. Work a job explains why to render rather than run chunks by hand.

Then the final. Once no marker is left, render_job(job, final = TRUE) renders the accepted result. It refuses an open marker, a skipped chunk, stop_here() and unregistered data, and it records the job's provenance beside the report.

Where to go next

  • rfr-explain reads what this job saves (rfr.rds). Add it to the same set, with this job's subject and type, because that shared pair is how it finds the file: add_job("rfr.explain", subject = "<subject>", type = "<type>").
