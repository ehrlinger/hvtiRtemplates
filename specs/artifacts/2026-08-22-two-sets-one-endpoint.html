The fork

One endpoint, two methods, two sets

Read down. The two chains are independent below the split — different machinery, different estimates, different figures — but they are not independent above it. Both need the Kaplan–Meier life table, and it is the same template both times.

shared data authored job set artifact directory the collision, if the type is dropped

The accepted cost: ac runs once per set rather than once per endpoint. One repeated life table buys a set that is self-contained and uniformly named — and it means a set can be deleted, re-run or handed to someone else whole.

Worth keeping

Practice already reached for nesting

The RF study template builds estimates/, graphs/ and distributions/ subfolders per analysis and caches its forest inside them, rebuilding only when the file is missing. That instinct is right and the design keeps it. Only the folder’s name changes — from a hand-typed date to the set key the filename already carries.

Check this one

A generated folder inside a source folder

That same template also creates ../distributions/rfsrc_survival_<date>/. Under the proposed rule distributions/ holds authored files only, flat — generated output belongs under graphs/ or estimates/. Either the rule needs a carve-out or that write needs rehoming, and biostats should say which.

Version the artifact, not the folder

rfsrc_surv_<rfsrc_ver>.rda stamps the fitted forest with the package version that produced it — so an rfsrc upgrade invalidates the cache instead of silently reusing it. That is a genuinely good idea and it survives unchanged: the set key names the directory, the version stays on the file.

The ordinals are provisional

04.19-rfs and 06.14-np above are illustrative — the minor digit is assigned in hvti_taxonomy() row order, and the random-forest rows were appended rather than placed. If the forest family deserves its own block rather than the tail of analyses, now is the moment, because nothing renumbers afterwards.

What is drawn and what is proposed. The dead_pa-hz chain is traced from the SAS templates and is real. The dead_pa-rfs chain is assembled from the random-forest templates in analyses/templates/, which exist but have never been run as a numbered set — its ordinals are the design’s, not observed. Only ac is templated in hvtiRtemplates today; everything else here is the shape being proposed, which is exactly what is up for debugging.
