The chain

One endpoint, one analysis type, nine jobs

The dead endpoint analysed by parametric hazard. Every job re-reads library.built and re-runs the %vars macro from scratch — there is no in-memory state between jobs. The only thing passed forward is a dataset in estimates/, addressed by name.

authored job (a .sas you edit) built dataset + %vars estimates/ handoff filed output hand-carried — no file, no check
Where the chain breaks

Four failure modes, and what each looks like from the outside

None of these raise an error. That is what makes them worth a diagram — every one of them produces a clean log and a plausible number.

Silent · most common

The shape went stale

hz is re-fitted and the new thalf, nu, m are never re-typed into hm’s fixthalf fixnu fixm parameters. hm still runs, still converges, still reports covariates — against the previous shape.

Symptom: hp’s overlay drifts from the life table, and only in one phase.

Silent

The name points somewhere else

The corpus holds est.hmdead, hmdead1, hmdeada, hmdead_s3la, hmdtn1sn — same prefix, same endpoint, distinguished by suffixes with no rule behind them. inhaz= takes whichever name is typed.

Symptom: predictions for the wrong model, correct in form.

Loud, once you look

Nobody wrote it

Across the template corpus 110 estimates members are read and 79 written; only 13 carry a handoff between two different jobs. The rest read something the writer left in another study, or write something no job reads back.

Symptom: ERROR: File EST.X does not exist — the one honest failure in this list.

Silent

%vars changed underneath

168 of 231 jobs %inc the same datasets/vars.sas and re-derive their variables at run time. Edit it for one job and every job downstream silently changes — but only when it is next re-run.

Symptom: two jobs in one set disagree about a variable, and both logs are clean.

The numbering

What the ordinal replaces

The SAS name says what a job is. It does not say when it runs — run order lives in the folder it sits in, which a reader has to already know. The R name carries both, so a set sorts into run order even when it is scattered across five directories.

Gaps are a statement, not an omission

A set that scaffolds ac, hz, hp produces 03.01, 03.02, 06.01 — never 01/02/03. The ordinal is fixed per prefix and identical in every study, so 03.01 means ac everywhere. A missing 02.xx positively says no descriptive job in this set.

One thing to check before we commit

hs is filed three different ways right now: the SAS files sit in graphs/templates/, the study README says distributions/, and the R taxonomy has moved it to analyses/, directly after the hm it consumes. The R position is the argued one — but it is the row most worth a second opinion.

How these numbers were produced. Every count on this page comes from a scan of the 231 .sas templates under ~/Documents/template, matching data est.<member> as a write and set / data= / inhaz= est.<member> as a read. One caveat worth stating plainly: the corpus is a library of examples drawn from many different studies, so an unmatched read usually means the writer lives in another study rather than that something is broken. The finding is not that 80 reads are defects — it is that the member name is the only thing joining a writer to a reader, and nothing checks it at either end.
